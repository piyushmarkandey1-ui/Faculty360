# A³P-Web — MVP Scope

> **SIH 2026 | PS64** — This document defines what is in scope for the hackathon demonstration.

---

## 1. MVP Objective

Demonstrate a working **end-to-end flow** from faculty onboarding through data ingestion, profile unification, and deterministic assessment — using Google Scholar data via Apify and manually provided institutional data.

The MVP must clearly communicate:
1. The **problem** of fragmented faculty data
2. The **data flow** from sources to unified profile
3. The **RULES CALCULATE / AI INTERPRETS / HUMANS DECIDE** principle in action
4. The **explainability and audit trail** of every assessment claim

---

## 2. MVP Feature Scope

### ✅ In Scope

| Feature | Route | Notes |
|---|---|---|
| **Landing page** | `/` | Hero with data flow visual, product explanation |
| **Login** | `/login` | Static auth with hardcoded demo credentials — no real auth backend yet |
| **Dashboard** | `/dashboard` | Platform summary: faculty count, ingestion status, avg completeness, conflict count |
| **Faculty Directory** | `/faculty` | Paginated list with search/filter, completeness badge, source coverage indicators |
| **Faculty Onboarding** | `/faculty/new` | Form to create a faculty entity with name, email, department, scholar_id |
| **Unified Faculty Profile** | `/faculty/[id]` | Full profile view: identity, metrics, publications, source coverage |
| **Data Review** | `/faculty/[id]/review` | Conflict resolution UI — resolve source disagreements field-by-field |
| **Assessment View** | `/faculty/[id]/assessment` | KPI score breakdown, confidence score, AI insight panel |
| **Evidence Trail** | `/assessment/[id]/evidence` | Per-claim evidence: source record links, field paths, rule version |

### ❌ Out of Scope (Post-MVP)

| Feature | Reason |
|---|---|
| Real JWT authentication | Time constraint; demo uses static credentials |
| ResearchGate ingestion | Source access is unreliable; Phase 2 |
| Scopus / WoS integration | Requires paid institutional API license |
| Student feedback / 360-degree appraisal | Different product surface; separate scope |
| NAAC / NIRF export reports | Complex formatting; Phase 3 |
| Multi-institution / tenant isolation | Single institution in MVP |
| Native mobile app | Web only |
| Real-time ingestion status (WebSocket) | Polling is sufficient for MVP |

---

## 3. MVP Data Strategy

For the SIH demonstration:

| Data Type | Source |
|---|---|
| Faculty entities | 5–10 pre-seeded faculty records (realistic anonymized or public data) |
| Google Scholar data | Real Apify runs on public scholar profiles (or realistic static fixtures) |
| Institutional data | CSV upload with pre-filled demo CSV |
| Conflict examples | At least 2 intentionally conflicting records across sources |
| Assessment results | Generated by running the rule engine on seeded profiles |
| AI insights | Real LLM API call on assessment result |

---

## 4. Technical MVP Constraints

| Concern | MVP Decision |
|---|---|
| Auth | Hardcoded demo credentials; no session management complexity |
| Database | Supabase (managed) — no local Postgres required |
| Backend deployment | Render / Railway free tier |
| Frontend deployment | Vercel |
| Apify | Free tier or trial; limited to 5 faculty ingestion runs |
| AI API | Direct LLM API call; no streaming in MVP |
| Background jobs | Synchronous polling in MVP (no Celery/ARQ) |

---

## 6. What Must Work for the Demo

1. **Admin opens `/faculty`** → sees a directory of faculty with completeness scores
2. **Admin clicks a faculty** → sees unified profile with source coverage indicators
3. **Admin navigates to `/faculty/[id]/review`** → sees 2 detected conflicts, resolves one
4. **Admin navigates to `/faculty/[id]/assessment`** → sees KPI breakdown, confidence score, and an AI insight paragraph
5. **Admin clicks an evidence link** → sees exactly which source record and field produced that score
6. **Evaluator can see that the score comes from rules, not AI**

## 7. Phase Roadmap (Post-SIH)

| Phase | Milestone |
|---|---|
| **MVP (SIH)** | Google Scholar + Institutional data, rule engine, AI insights, demo UI |
| **Phase 2** | ResearchGate ingestion, real JWT auth, Supabase production, conflict resolution workflows |
| **Phase 3** | ORCID integration, Shodhganga, NAAC/NIRF export, configurable KPI framework UI |
| **Phase 4** | Scopus/WoS integration (institutional license), multi-department analytics, RBAC for faculty members |
| **Phase 5** | Multi-tenant SaaS, custom domain per institution, API for third-party integrations |
